Zustand stores in `src/store/` (barrel `index.ts`):

- **`useStore.ts`** (global app state): `mode` (light/dark) + theme, `primaryAccentColor`, sidebar state (`sideBarOpen`, `pinSideBar`, `fixedOpen`), `selectedWarehouse`/`warehouses`, `currTeObjArray`, `stackTitle`/`sidebarStack` (breadcrumb/nav stack), `language`/`allLanguages`, `searchLevel`, `snackbar`/`bulkActionDetails`, `mainMenuData`, `systemParams`, AI-chat & online-help dock flags. Selected warehouse persisted in localStorage.
- **`uiCoordinationStore.ts`** (cross-component event bus, the sync backbone): nonce-based events + per-key request maps. **Key shape as shipped to `dev-ng` — there are TWO keys and the split is deliberate:** `getStoreKey(scope)` (`objectScope.ts:94`) is **warehouse-INDEPENDENT**, so a warehouse switch does not reset every TE's mode or clear its selected row; `getFilterStoreKey(scope)` (`:82`) keeps the warehouse and is used ONLY by `searchFieldsByKey` + the three filter request channels (`hiddenFiltersByKey` stays on the plain key). A second registry `filterScopesByKey` exists so `clearObjectScopedState` still finds the differently-keyed filter slices, and `ScreenScope = Omit<StoreScope, "objId" | "warehouseId">` stops CustomPage's screen-wipe layout effect firing on a warehouse switch. Accepted hazard, deliberately unguarded: a selected row survives a warehouse switch and may point at a record absent from the new warehouse. **`te_search_*` persistence is NOT in the store** — it lives in `src/components/tableeditor/searchFieldsStorage.ts` (`readPersistedSearchFields`/`persistSearchFields`, `sessionStorage`), called from `useTableEditor`; `columnsStorageKey` deliberately stays on `localStorage`. Types in `src/types/objectScope.ts` (`StoreScope`/`ObjectScope`/`ScreenScope`), helpers in `src/utils/objectScope.ts`. The TE-mode slice is still `currentTableEditorModes: Record<string, Maybe<TableEditorCurrentMode>>` (+`setCurrentTableEditorModes`) — unchanged on dev-ng. **Slices were renamed in the same refactor** — the selected row → **`activeRowsByKey`** (+`setActiveRow`, ONE row per key; the designed `{row, seedRow}` pair was never implemented — `forcedViewRow` is derived in `ComponentMapper` as `isViewMode ? activeRow : null`), plus new `objectScopesByKey` (cumulative registry driving cleanup), `cardCollapsedByKey`/`cardToggleRequestsByKey` (state vs one-shot command), `searchFieldsByKey`, `hiddenFiltersByKey`. `screensSideBySide` is now `Record<screenKey, {sideBySide, isUserOverride}>`. Also `editEnabled` (builder edit toggle). Cleanup: `clearObjectScopedState`/`clearObjectStateForScreen(scope)`/`clearDialogTemporaryState(dialogId)`. **TE data events** (each `{nonce, payload:{objId,screenId,dialogId,…}}`): `teRowInsertedEvent`, `teRowUpdatedEvent`, `teRowsUpdatedEvent`, `teRowDeletedEvent`, `teDataChangedEvent`. **Requests**: `requestCardExpand`, `requestTeOpenSearch`, `requestTeRemoveFilter`, `requestTeClearAllFilters`, `requestOpenTeInsertModal`, `emitTeApplyPreviewFilter`, `emitTeExitView`, `emitTeTriggerEdit`, `emitTeNavigate`. Linked-preview readiness: `linkedPreviewReadyByUniqueId`/`setTeLinkedPreviewReady`. EditorsContext subscribes to the TE events to sync editors ([[frontend-editors-sync]]).

  - **Branch-only, not yet on dev-ng** (an unmerged object-scope-core rework branch, `src/store/uiCoordinationStore.ts`): on this branch, `currentTableEditorModes` is renamed to **`tableEditorModesByKey`** (+`setTableEditorMode`, line 118/539), and the search/filter request slices are renamed from `requestTeOpenSearch`/`requestTeRemoveFilter`/`requestTeClearAllFilters` to **`requestOpenSearch`/`requestRemoveFilter`/`requestClearAllFilters`** (lines 150-162), with matching consumers `consumeOpenSearchRequest`/`consumeRemoveFilterRequest`/`consumeClearAllFiltersRequest`. On dev-ng today the old names above are still correct — re-verify this whole note once that branch merges.
- **`useDrillDownStore.ts`** (drill-down hierarchy): `nodes: Record<id, DrillDownNode>` (+ `childrenByParentId`, `nodesByObjectId`). `DrillDownNode` = {id, parentId, children, visible, acObject?(CommonAppComponent), acMode, acFilters, screenId, screen?(ScreenObj), screenMode(0=SCREEN,1=MODAL), screenObjectId, screenObjectFilters, updatedAt}. API: `addOrUpdateNode(node|nodes, skipParentCheck?)`, `removeSubtree`, `getNode`, `getChildNodes`, `getTreeRootNode`, `getBreadcrumbs(nodeId, menuItems, skipRootNode)`. Node ids from `DrillDownNodeIdBuilder`. Drives nested screen/AC replacement & breadcrumbs.
- **`useFloatingDialogsStore.ts`**: `dialogs: FloatingDialog[]` {id, screenId, teId, source(FLOATING_DIALOG_SOURCE: `linked-textbox`|`ac-drill-down`), createdAt, expanded, minimized, minimizedLocked, drillDownNodeId, …}. API: `addDialog`, `openOrRestoreDialog`, `updateDialog`, `removeDialog`, `minimizeDialog`, `restoreDialog`, `bringToFront`. Linked-textbox dialogs persist minimized across navigation.

React contexts in `src/contexts/`: **EditorsContext** (editor sync — see [[frontend-editors-sync]]), **LinkedDialogContext** (flags rendering inside a linked dialog), **StepWizardContext**. Also `services/authContext.tsx`, `services/DrillDownNodeContext.tsx` (`useDrillDownNodeId`, `DrillDownNodeProvider`).
